# Multi-Repository Workspace Coordination

Map ownership and working state before choosing where to write. Do not treat a
shared parent directory as one repository.

## Workflow

1. Discover the workspace.

   Resolve every candidate repository to an absolute path. Record its remote,
   branch, HEAD, upstream, dirty state, worktrees, and applicable instruction
   files. Fetch the intended upstream before choosing a base and record a fetch
   failure rather than treating cached remote state as current. Prefer
   repository-provided resolver commands when available.

2. Classify artifacts.

   Assign each requested artifact to exactly one owner: public product,
   reusable public plugin, private operator configuration, generated output,
   ephemeral evidence, or secret store. A private repository is not a secret
   store. Never copy raw logs, credentials, private endpoints, or personal
   paths into a public repository.

3. Protect existing work.

   Treat tracked and untracked changes as user-owned. Do not reset, checkout,
   clean, stash, move, or reformat unrelated files. If the active branch is
   unrelated, create an isolated named worktree from the intended base after
   verifying the target path is unused.

4. Define the change graph.

   List repository-local changes, cross-repository contracts, generation or
   synchronization steps, validation owners, and landing order. Avoid a
   circular dependency where neither repository can pass independently.

5. Execute repository by repository.

   Read each repository's instructions and source-of-truth files before
   editing. Keep commits and diffs independently reviewable. Use absolute paths
   or explicit working directories so a command cannot land in the wrong
   checkout.

6. Verify boundaries and synchronization.

   Run each repository's focused tests, validators, secret scan, and diff
   checks. When files must be synchronized, compare generated bytes or use the
   repository's supported synchronization command; do not maintain silent
   manual copies.

7. Hand off durable state.

   Report a table with repository, path, branch, base revision, dirty state,
   files changed, validation, dependency/landing order, and remaining action.
   State explicitly which repositories were inspected but not changed.

## Stop conditions

Stop and request direction when ownership cannot be resolved, a required base
revision is unavailable, the only safe target overlaps unrelated dirty work,
or completion requires moving data across a public/private/secret boundary.

Do not claim coordinated completion until every changed repository has its own
validation result and the cross-repository contract is checked.
